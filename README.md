## 1. 项目简介

### 这个工具是做什么的

MXD-GGV 是一个运行在 Windows 上的桌面小工具（Go + Wails + React 单文件 exe）。它做三件事：

1. **看**：把选定的游戏窗口以低帧率截图，实时显示在自己的界面里，供你框选感兴趣的区域（ROI）。
2. **认**：对框选出的「血药格 / 蓝药格 / 血条 / 蓝条」做模板匹配与数字字形匹配，读出快捷栏里剩余的药水数量。
3. **提醒**：数量低于阈值或判定为空时，弹出 Windows 系统通知，并在游戏画面顶部投放一条点击穿透的弹幕提示。

此外提供一个**宠物饱满感辅助**模块：按固定节奏在本地模拟饱满感衰减，低于阈值时向游戏窗口发送一次喂食快捷键。

### 主要解决什么问题

长时间挂机练级时，最容易出事的是「药水悄悄用完了」和「宠物饿了不吃东西」。这两件事都不难做，但需要人一直盯着屏幕角落的两个小数字。本项目把「盯屏幕」这件重复劳动交给程序，把注意力还给玩家。

### 适合什么场景

- 长时间单点刷怪、需要偶尔离开键盘的场景
- 屏幕较大 / 多显示器，血蓝药数量在视野边缘不易察觉
- 作为**图像识别、Windows 桌面自动化、Wails 桌面应用**的学习与实践样本

### 整体设计思路

- **只读优先**：核心能力（截图、识别、提醒）完全不向游戏写入任何东西，只是把屏幕上已有的信息读出来告诉你。唯一会产生输入的模块是宠物喂食（发送一次按键）。
- **人工校准 + 相对坐标**：不内置任何分辨率写死的坐标。所有区域由用户在预览图上框选，以 `0–1` 的相对坐标保存，换分辨率后按比例缩放仍然可用。
- **多重证据 + 防抖**：单帧识别一定会偶尔出错。因此数量读数、模板相似度、血蓝条填充率三路证据互相校验，并要求状态连续多帧一致才对外报警，避免动画/特效导致的误报。
- **不做规避**：本项目不包含、也不打算包含任何针对反作弊机制的隐藏、注入或检测规避手段。

> ⚠️ 本项目仅用于**技术学习、图像识别研究与桌面自动化实践**。请在遵守游戏运营商用户协议与当地法律法规的前提下使用，详见 [游戏规则与风险提示](#10-游戏规则与风险提示) 与 [免责声明](#15-免责声明)。

## 2. 功能特性

### ✅ 已实现

**窗口识别与画面捕捉**

- 枚举当前可见窗口（标题、进程名、PID、窗口尺寸、是否隐藏）
- 按标题/进程名关键字自动标记疑似冒险岛窗口（`MapleStory`、`冒险岛`、`冒險島`、`新楓之谷`、`메이플스토리`、`メイプルストーリー`、`Maple.exe`）
- 对选定窗口实时截图预览，帧率 1–30 FPS、JPEG 画质 20–95、预览宽度可调
- 预览区支持滚轮缩放、右键平移、双击复位，方便框选细小的 UI 元素
- 状态栏实时显示实际帧率与单帧捕捉耗时
- 捕捉线程主动降低优先级，尽量减少对游戏本身的干扰

**药量识别与提醒**

- 在预览图上框选四类区域：血药格、蓝药格、血条、蓝条（任选其一即可开始工作）
- 「校准」一键完成：截取药槽模板、采样血蓝条 HSV 色域、并**自动读出画面里当前的药水数量**（数量无需手填）
- 数字识别使用游戏原始字形做像素级模板匹配，覆盖 1x–3x UI 缩放
- 三路判据融合：数字读数 → 模板归一化相关系数（NCC）→ 血蓝条填充率
- 状态防抖：连续帧确认、跨帧读数合理性校验（过滤 `188 → 1` 这类误读）、状态锁存
- 三档状态输出：充足（ok）/ 不足（low）/ 已空（empty），另有 unknown / absent 两种未确定态
- 提醒方式：Windows 系统 Toast 通知（失败时退回系统提示音）+ 界面高亮 + 游戏窗口上方的**点击穿透弹幕**
- 提醒冷却机制，避免同一状态反复轰炸；`low → empty` 升级时可立即再次提醒
- 校准结果自动持久化，下次启动自动恢复框选

**宠物饱满感辅助**

- 本地维护饱满感数值：每 1 分钟 −1，低于 70 时发送一次喂食快捷键并 +30，上限 100
- 喂食快捷键可自定义：F1–F12、字母、数字、小键盘、`Insert`/`Delete`/`Home`/`End`/`PageUp`/`PageDown`/方向键等
- 界面实时显示当前饱满感、下次衰减倒计时、累计喂食次数
- 权限自检：检测到游戏以管理员身份运行而本程序未提权时给出提示，并提供「以管理员身份重启」按钮（走标准 UAC）
- 发键失败（如被系统拒绝）时保持数值不变并显示错误原因，不做静默重试

**工程化**

- 全部核心逻辑带单元测试（按键解析、饱满感衰减、数字识别、状态机、截图编码等）
- GitHub Actions CI：gofmt 检查 + `go vet` + `go test` + `wails build`
- GitHub Actions Release：打 tag 自动出便携版 zip、NSIS 安装包与 `SHA256SUMS.txt`
- Dependabot 每周检查 Go / npm 依赖

### 🧩 计划支持 / 可扩展（当前尚未实现）

以下条目**目前不存在于代码中**，列出以说明架构的扩展方向：

- 📄 **可编辑的配置文件**：当前仅自动保存校准数据（见 [配置说明](#6-配置说明)），运行参数需在界面调整，尚无用户可手工编辑的 YAML/TOML 配置
- 📝 **日志系统**：当前错误只呈现在界面上，尚未落盘为日志文件
- ⌨️ **全局启停热键**：当前启动/停止需在界面点击按钮，尚无系统级全局热键
- 🧰 **自定义任务流程 / 脚本编排**：尚无任务 DSL 或脚本引擎
- 🖱️ **鼠标操作能力**：后端已封装后台点击接口（`vision.Click` / `vision.ClickWindow`），但**未接入界面**，当前不对外提供
- 🔔 **更多提醒通道**：如声音自定义、Webhook、手机推送
- 🌐 **多语言界面**：当前界面为简体中文
- 🖥️ **多窗口 / 多开同时监测**：当前一次只监测一个窗口

## 3. 项目结构

```text
mxd/
├── main.go                     # 程序入口：Wails 应用启动、嵌入前端产物
├── app.go                      # Wails 绑定层：把 Go 方法暴露给前端
├── wails.json                  # Wails 项目配置（应用名、构建脚本、版本信息）
├── go.mod / go.sum             # Go 依赖
│
├── internal/
│   ├── vision/                 # 窗口枚举、实时截图预览、JPEG 编码、鼠标封装
│   ├── wincap/                 # 平台相关的窗口/屏幕抓取实现（Windows GDI，含非 Windows 回退）
│   ├── potion/                 # 药量识别核心
│   │   ├── potion.go           #   服务生命周期、采样循环
│   │   ├── detect.go           #   校准构建、单帧分析
│   │   ├── slot.go / bar.go    #   药槽模板匹配 / 血蓝条填充率
│   │   ├── digits.go           #   数字切分与匹配
│   │   ├── stencil.go          #   原始字形多尺寸模板库
│   │   ├── glyphs.go           #   内嵌字形资源解析
│   │   ├── state.go            #   状态机与防抖、提醒冷却
│   │   ├── persist.go          #   校准数据持久化
│   │   ├── notify_windows.go   #   Windows Toast 通知
│   │   ├── assets/digits/      #   0–9 数字字形图（内嵌）
│   │   └── testdata/           #   识别用测试样本
│   ├── petfeed/                # 宠物喂食：饱满感逻辑、按键发送、UAC 提权
│   └── overlay/                # 游戏窗口上的点击穿透弹幕提示
│
├── frontend/
│   ├── src/                    # React + TypeScript 界面（预览、框选、控制面板）
│   ├── wailsjs/                # Wails 自动生成的前端绑定（勿手改）
│   ├── package.json            # 前端依赖与构建脚本
│   └── dist/                   # 前端构建产物（被 go:embed 嵌入，不入库）
│
├── build/                      # Wails 构建资源（图标、NSIS 安装包模板）
└── .github/workflows/          # CI / Release 流水线
```

### 主要目录用途

| 目录 | 用途 |
| --- | --- |
| `internal/vision` | 窗口列表、实时预览的采样循环与帧编码，前端预览图的数据来源 |
| `internal/wincap` | 抓帧的平台实现，按构建标签分离 Windows / 非 Windows |
| `internal/potion` | 项目的技术核心：校准、图像识别、状态判定、提醒触发 |
| `internal/petfeed` | 唯一会向游戏发送输入的模块，含权限检测 |
| `internal/overlay` | 覆盖在游戏窗口上的提示层，不抢焦点、不拦截点击 |
| `frontend/src` | 全部用户界面；框选交互与参数控件都在这里 |

## 4. 环境要求

### 运行环境（使用者）

| 项目 | 要求 |
| --- | --- |
| 操作系统 | **Windows 10 / 11 x64**（本项目依赖 Windows GDI 抓屏、`SendInput`、WebView2，**不支持 Linux / macOS**） |
| 运行时 | [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)（Win11 已内置；Win10 若缺失，Wails 会提示安装） |
| 权限 | 普通用户即可运行。若游戏客户端以管理员身份运行，则本程序也需「以管理员身份运行」，否则发送按键会被系统拒绝 |
| 游戏客户端 | 需为**窗口化 / 无边框窗口**模式，且窗口未最小化。独占全屏可能导致抓帧失败或画面异常 |
| 分辨率 / DPI | 无固定分辨率要求（区域使用相对坐标）。但 **DPI 缩放变化、游戏窗口尺寸变化、UI 缩放档位变化后建议重新校准** |

## 5. 安装与配置

### 方式一：直接使用发布版（推荐给普通使用者）

1. 到仓库 **Releases** 页面下载对应 tag 的产物：
   - `mxd-<tag>-windows-amd64.zip` — 便携版，解压即用
   - `mxd-<tag>-windows-amd64-installer.exe` — NSIS 安装包
2. 用 `SHA256SUMS.txt` 校验文件完整性：

   ```powershell
   Get-FileHash .\mxd-<tag>-windows-amd64.zip -Algorithm SHA256
   ```

3. 解压并运行 `mxd.exe`。

> ℹ️ 发布产物**未做代码签名**，首次运行会触发 Windows SmartScreen 提示，属预期现象。

### 方式二：从源码构建（开发者）

```bash
# 1. 获取项目
git clone https://github.com/lnatpunblhna/mxd-ggv.git
cd mxd-ggv

# 2. 安装 Wails CLI
go install github.com/wailsapp/wails/v2/cmd/wails@v2.15.0

# 3. 安装前端依赖
cd frontend && npm ci && cd ..

# 4. 开发模式（前端热重载）
wails dev

# 5. 构建生产版本 → build/bin/mxd.exe
wails build -platform windows/amd64 -trimpath -ldflags "-s -w"

# 6.（可选）连同 NSIS 安装包一起构建
wails build -platform windows/amd64 -nsis -clean -trimpath -ldflags "-s -w"
```

`wails dev` 另会在 `http://localhost:34115` 启动调试服务，可在浏览器 devtools 里直接调用 Go 方法。

### 首次配置

本项目**没有需要手工编辑的配置文件**，配置全部在界面完成：

1. 启动游戏，确保处于窗口化模式
2. 启动 `mxd.exe`（若游戏以管理员运行，请一并提权）
3. 在窗口列表中选择游戏窗口 → 点「▶ 开始预览」
4. 依次框选「血药格」「蓝药格」（可选「血条」「蓝条」）→ 点「校准」
5. 设置「低量阈值」→ 点「开启」

## 6. 配置说明

### 6.1 校准数据文件（程序自动生成）

校准结果保存在用户配置目录下，**由程序自动读写，通常无需手改**：

```text
%AppData%\mxd\potion\
├── calib.json    # 框选区域、血蓝条色域、校准时读到的数量
├── hp.png        # 血药格模板图
└── mp.png        # 蓝药格模板图
```

`calib.json` 示例（**以下为示例数据，实际数值由校准生成**）：

```json
{
  "hpSlot": { "x": 0.4180, "y": 0.9410, "w": 0.0250, "h": 0.0330 },
  "mpSlot": { "x": 0.4460, "y": 0.9410, "w": 0.0250, "h": 0.0330 },
  "hpBar":  { "x": 0.3520, "y": 0.9210, "w": 0.0600, "h": 0.0080 },
  "mpBar":  { "x": 0.3520, "y": 0.9310, "w": 0.0600, "h": 0.0080 },
  "hpCol":  { "hMin": 350, "hMax": 18,  "sMin": 0.35, "vMin": 0.25 },
  "mpCol":  { "hMin": 195, "hMax": 255, "sMin": 0.30, "vMin": 0.25 },
  "frameW": 1920,
  "frameH": 1080,
  "hpCount": 188,
  "mpCount": 339
}
```

| 字段 | 含义 |
| --- | --- |
| `hpSlot` / `mpSlot` | 血药格 / 蓝药格区域，**相对窗口客户区的比例坐标**（`x`/`y` 为左上角，`w`/`h` 为宽高，取值 0–1） |
| `hpBar` / `mpBar` | 血条 / 蓝条区域，同为相对坐标；用于「药槽认不出来时」的兜底判据 |
| `hpCol` / `mpCol` | 血/蓝条的 HSV 色域。`hMin`/`hMax` 为色相（0–360，允许跨 0° 环绕），`sMin`/`vMin` 为饱和度/明度下限 |
| `frameW` / `frameH` | 校准时的画面像素尺寸，仅作参考记录 |
| `hpCount` / `mpCount` | 校准瞬间识别到的药水数量，作为开启监测时的基准值 |

> 🔧 手工修改此文件属于**高级操作**。文件损坏或字段非法时，程序会视为「未校准」并要求重新框选，不会崩溃。删除整个目录即可恢复出厂状态。

### 6.2 运行参数（界面控件）

以下参数在界面上调整，**不落盘**，每次启动回到默认值：

| 分组 | 参数 | 范围 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| 预览 | 帧率 | 1–30 FPS | 8 | 抓帧频率。越高越流畅，CPU 占用也越高 |
| 预览 | 画质 | 20–95 | 70 | 预览图 JPEG 质量，仅影响显示，不影响识别 |
| 预览 | 预览宽度 | 320–1920 px | 960 | 预览图缩放宽度，仅影响显示 |
| 药量 | 低量阈值 | 0–999 | 10 | 数量 ≤ 该值判为「不足」。设为 0 表示只在判定为空时提醒 |
| 宠物 | 当前饱满感 | 0–100 | — | 启动时需手填一次，作为本地计数起点 |
| 宠物 | 喂食快捷键 | — | — | 点击输入框后按下目标按键即可录入 |

### 6.3 内部常量（需改代码，仅供参考）

这些值当前**未暴露到界面**，如需调整请修改源码并重新构建：

```go
// internal/potion/types.go — WatchOptions 默认值
IntervalMS     = 500    // 采样间隔（毫秒），有效范围 200–3000
EmptyFrames    = 6      // 状态需连续多少帧一致才对外确认
CooldownSec    = 180    // 同级别提醒的冷却秒数
BarLow         = 0.40   // 血蓝条填充率低于该比例视为偏低
BarStuckFrames = 6      // 血蓝条持续偏低多少帧才判定为「药可能已空」

// internal/petfeed/logic.go — 宠物喂食节奏
```

## 8. 工作原理

### 8.1 画面捕捉

- 通过 `user32`/`gdi32` 的 `GetDC` + `BitBlt` + `GetDIBits` 抓取窗口所在屏幕区域，得到 BGRA 原始像素
- 抓帧线程调用 `SetThreadPriority` 降到 `BELOW_NORMAL`，尽量把 CPU 让给游戏
- 预览帧转 RGBA 后编码为 JPEG、Base64 传给前端；前端用**长轮询 + 序号**取帧，避免高频事件淤积
- 非 Windows 平台保留了基于 `go-game-vision` 的回退实现，仅用于让代码可编译与跑单元测试

### 8.2 区域校准

- 所有框选以相对坐标（0–1）保存，检测时按当前帧尺寸换算为像素矩形
- 药槽：截下当前像素作为**模板图**，同时统计平均饱和度与亮度标准差
- 血蓝条：取条左侧四分之一区域采样 HSV 中位数，自动推导出该条的色域范围（比写死红/蓝更耐受不同 UI 皮肤）

### 8.3 药水数量识别（本项目的技术重点）

不使用通用 OCR，而是用游戏自身的数字字形做**像素级模板匹配**：

1. `internal/potion/assets/digits/0-9.png` 是游戏原始数字字形（8×11，`1` 为 5×11；黑色描边 + 白到淡蓝渐变字身）
2. 为 1x–3x UI 缩放、以及截图缩放可能吃掉的行/列，预生成多档模板库（`stencil.go`）
3. 匹配时同时校验两件事：
   - **字身**位置必须是字体配色的亮点（命中率 ≥ 0.86）
   - **描边**位置必须接近纯黑（命中率 ≥ 0.68）
4. 药水图标的白色高光能骗过单纯的亮度二值化，但骗不过整圈黑色描边——这是本方案比「二值化再切分」稳得多的原因
5. 同一串数字强制使用同一档尺寸模板，避免出现「3 里面认出个 1」这类错位

### 8.4 状态判定与防抖

单帧结果先经过合理性过滤，再进入状态机：

- **读数合理性**：`plausibleCount` 拦截不像真实用药的跳变。例如 `188 → 1`（丢首位）、`339 → 300`（9 被认成 0）会被判为误读并沿用上一次读数；`12 → 9`（正常跨 10）、`50 → 300`（买药补货）则放行
- **多路证据优先级**：读到数字 → 以数量为准；读不到 → 看模板 NCC；两者都不确定 → 看血蓝条填充率是否持续偏低且无回升
- **连续帧确认**：状态需连续 `EmptyFrames`（默认 6）帧一致才锁存，避免技能特效、弹窗遮挡造成的瞬时误判
- **提醒冷却**：同级别提醒 `CooldownSec`（默认 180 秒）内不重复；`low → empty` 升级时立即再报一次

### 8.5 提醒通道

- **系统通知**：`go-toast` 推送 Windows Toast；推送失败退回 `MessageBeep`
- **界面高亮**：通过 Wails 事件把状态推给前端
- **画面弹幕**：分层窗口（`WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_NOACTIVATE`）覆盖在游戏窗口上方，**点击穿透、不抢焦点**，在画面上方带状区域循环滚动提示文字

### 8.6 宠物喂食

- 饱满感完全在本地按固定节奏推算（**不读取游戏内数值**），因此需要用户启动时手填一次起点
- 低于阈值时通过 `SendInput`（扫描码方式，含扩展键标记）发送一次按键
- 发键前需要窗口获得焦点：`ShowWindow(SW_RESTORE)` + `AllowSetForegroundWindow` + `AttachThreadInput` + `SetForegroundWindow`，成功后等待 50ms 再发键，按下保持 120ms
- 因此**喂食瞬间会切到游戏窗口**，这是 Windows 的输入模型决定的，不是缺陷

### 8.7 可选实现方案（当前未采用）

下列技术方案对本项目适用，但**尚未实现**，供扩展参考：

- Windows Graphics Capture / DXGI Desktop Duplication 替代 BitBlt，降低抓帧开销
- Tesseract / PaddleOCR 等通用 OCR 引擎替代字形模板（通用性更好，但延迟与误识别率更高）
- `RegisterHotKey` 实现全局启停热键
- `PostMessage`/`SendMessage` 后台发键（不抢焦点，但对多数游戏客户端无效，可靠性差）
- 结构化日志（`log/slog`）+ 日志轮转
- 任务调度器 / 状态机 DSL，支持用户自定义流程

## 9. 安全与稳定性

### 已有的保护措施

- **参数夹取**：所有对外参数在入口处规范化（帧率 1–30、画质 20–95、采样间隔 200–3000ms、饱满感 0–100），非法值不会传入内部逻辑
- **框选校验**：区域过小（宽或高 < 0.4% 画面）视为无效，拒绝校准；未校准时禁止开启监测
- **重复启动保护**：服务已在运行时再次调用 `Start` 直接返回错误，不会出现两个采样循环
- **失败不静默**：抓帧失败、发键被拒绝等错误写入状态并显示在界面，且**发键失败时不修改饱满感**，避免数值与实际脱节
- **优雅退出**：程序退出时按序停止弹幕层、喂食服务、监测服务与截图会话，`context` 取消 + 等待协程收敛
- **降低干扰**：抓帧线程降优先级；弹幕窗口点击穿透、不抢焦点
- **提醒节流**：冷却机制避免通知轰炸

### 建议与注意事项

- ⏹️ **紧急停止**：当前**没有全局热键**。最快的停止方式是 `Alt+Tab` 切回本程序点「关闭」，或直接关闭程序窗口（会停止全部任务）。极端情况可用任务管理器结束 `mxd.exe`
- 🖐️ **防误操作**：宠物喂食会真实发送按键并切换窗口。请确认快捷键与游戏内设置一致，且该键位在游戏里不会触发交易、丢弃、使用道具等**不可撤销**的操作
- ⏱️ **操作间隔**：喂食连发之间有 400ms 间隔，发键前后有焦点稳定与按键保持延时；请勿把衰减间隔改到极小值
- 🔐 **权限最小化**：仅在游戏以管理员运行时才需要提权。提权走标准 UAC，不做任何绕过
- 🔒 **不涉及账号凭据**：本项目**不读取、不存储、不传输**账号、密码、Token 等任何凭据。持久化文件只有校准坐标与两张小尺寸模板图
- 🌐 **无网络行为**：核心功能不联网。请勿在本项目中加入上传游戏数据的代码
- ⚠️ **不要运行来源不明的构建**：请从源码自行构建，或从官方 Releases 下载并核对 `SHA256SUMS.txt`。第三方修改版可能植入恶意代码
- 🔁 **换环境要重新校准**：改分辨率、改 DPI 缩放、改游戏 UI 缩放、换显示器之后请重新校准

## 11. 开发说明

欢迎以 Issue / Pull Request 参与改进。

### 代码约定

- Go 代码必须通过 `gofmt`（CI 会拒绝未格式化的提交）
- 平台相关代码用构建标签分离：`xxx_windows.go` / `xxx_other.go`，保证非 Windows 下仍可编译与测试
- 注释与界面文案使用简体中文；注释解释**为什么**这样写，而不是复述代码
- `frontend/wailsjs/` 由 Wails 自动生成，请勿手工修改

### 添加新的任务模块

1. 在 `internal/` 下新建包，参照 `petfeed` / `potion` 的服务结构：
   - `Service` 结构体 + `New()`
   - `Start()` / `Stop()` / `Status()` / `Close()`
   - `SetEmitter(func(Status))` 用于向前端推送状态
   - 内部用 `context.Context` 控制生命周期，`sync.Mutex` 保护状态
2. 在 `app.go` 里为 `App` 添加导出方法（Wails 只绑定导出方法）
3. 在 `startup()` 里接好 `SetEmitter` → `runtime.EventsEmit`
4. 在 `shutdown()` 里加上清理逻辑
5. 运行 `wails dev`，Wails 会自动重新生成 `frontend/wailsjs/` 绑定
6. 在 `frontend/src/App.tsx` 增加对应面板

### 添加新的识别方式

- 单帧识别逻辑放进 `internal/potion/`（或新包），保持**纯函数**风格：输入图像 + 参数，输出判据，不碰全局状态
- 状态判定与防抖统一走 `state.go` 的 tracker 模式，别在识别层直接触发提醒
- 新增识别器请配套测试样本：小尺寸 PNG 放 `testdata/`，或用 `stencil_synth_test.go` 的方式**合成**测试图（更稳定、不依赖真实截图）

### 扩展配置项

- 运行期参数加到 `potion.WatchOptions` / `vision.Options`，并在 `normalize()` 里补上范围夹取
- 需要持久化的字段加到 `internal/potion/persist.go` 的 `persisted` 结构体，注意**向后兼容**：旧文件缺字段时要能回退到默认值
- 前端在 `App.tsx` 增加控件并传入对应 API

### 增加新的快捷键

- 键名解析集中在 `internal/petfeed/keys.go`：新键位加进 `namedKeys` 映射，扩展键需同步更新 `isExtendedKey`
- 前端录键使用 `KeyboardEvent.code`，后端 `ParseKey` 同时兼容 `code` 与常见别名（如 `Insert`/`ins`/`INS`）
- 加键位请同时在 `petfeed_test.go` 的 `TestParseKey` 里补用例

## 12. 常见问题 FAQ

<details>
<summary><b>为什么识别不到游戏窗口？</b></summary>

依次检查：

1. 游戏是否已启动并**未最小化**（最小化的窗口无法抓帧）
2. 是否处于**独占全屏**模式 → 改为窗口化或无边框窗口
3. 点击「刷新」重新枚举窗口
4. 窗口列表里没有高亮标记也没关系——自动标记只按标题/进程名关键字猜测，**手动选中同样可用**。可按窗口尺寸和进程名（如 `MapleStory.exe`、`Maple.exe`）辨认
5. 窗口标题为空或尺寸小于 160×80 的窗口会被过滤掉
6. 若游戏以管理员身份运行，请同样以管理员身份运行本程序
</details>

<details>
<summary><b>为什么按键没有生效？</b></summary>

1. **权限不足**：最常见原因。游戏以管理员运行时，非提权进程的 `SendInput` 会被系统拒绝（`Access is denied`）。界面会给出提示，点「以管理员身份重启」即可
2. **快捷键不匹配**：确认录入的键与游戏内实际设置的喂食键一致
3. **焦点切换失败**：若出现「无法切换到游戏窗口」，先手动点一下游戏窗口再试
4. **游戏窗口被遮挡或最小化**：恢复窗口后重试
5. 具体错误原因会显示在宠物面板下方的错误行里
</details>

<details>
<summary><b>DPI / 缩放导致坐标不准确怎么办？</b></summary>

框选使用相对坐标，对窗口尺寸变化天然有一定适应性，但以下情况需要**重新校准**：

- 修改了 Windows 显示缩放（125% / 150% 等）
- 修改了游戏分辨率或 UI 缩放档位
- 把游戏窗口拖到了不同缩放比例的显示器上
- 在窗口化与全屏之间切换

重新校准的成本很低：重新框选 → 点「校准」即可。

若数字识别始终不准，尝试：把游戏 UI 缩放调到 1x/2x/3x 这类整数档位（识别模板按整数倍缩放构建）、框选时把框贴紧数字区域、放大预览后再框。
</details>

<details>
<summary><b>如何紧急停止？</b></summary>

当前**没有全局热键**（已列入计划）。按可靠性排序：

1. `Alt+Tab` 切回本程序 → 点对应面板的「关闭」/「停止」
2. 直接关闭程序窗口 —— 退出流程会停止全部后台任务并清理弹幕层
3. `Ctrl+Shift+Esc` 打开任务管理器 → 结束 `mxd.exe`

需要注意：药量提醒模块是**只读**的，不会对游戏产生任何输入；真正需要紧急停止的只有宠物喂食模块。
</details>

<details>
<summary><b>程序报错怎么办？</b></summary>

1. 界面上的红色错误条会显示具体原因，先按提示处理（多数是「未选择窗口」「请先校准」「权限被拒绝」这三类）
2. 抓帧类错误（窗口已关闭、句柄失效）通常重新「刷新」并重选窗口即可
3. 校准数据损坏：删除 `%AppData%\mxd\potion\` 目录后重新校准
4. 界面白屏 / 打不开：确认已安装 WebView2 Runtime
5. 仍无法解决 → 提交 Issue，附上下方 [故障排查](#13-日志与故障排查) 所列信息
</details>

<details>
<summary><b>识别到的数量偶尔跳变 / 明显读错怎么办？</b></summary>

程序内置了跳变过滤（见 [8.4](#84-状态判定与防抖)），会拦掉大部分误读并沿用上一次读数。若仍频繁读错：

1. 重新框选，让框更贴合数字，避免框入相邻图标或背景装饰
2. 把游戏 UI 缩放设为整数档位
3. 同时框选「血条」「蓝条」，为程序提供第二路判据
4. 若能复现，请在 Issue 中附上药槽区域的**截图片段**（可直接用界面上的模板缩略图区域截图），便于补充测试样本
</details>

<details>
<summary><b>如何提交 Bug？</b></summary>

到仓库 Issues 页面新建 Issue，请包含：

- 问题描述与**复现步骤**
- 期望行为 vs 实际行为
- 环境信息：Windows 版本、显示缩放、屏幕分辨率、游戏窗口尺寸、游戏 UI 缩放档位
- 程序版本（Release tag 或 commit hash）
- 界面上显示的完整错误文案（截图最好）
- 识别类问题：附上药槽区域截图（**请自行遮挡角色名、ID 等个人信息**）

⚠️ 提交前请务必**移除截图中的账号、角色名等敏感信息**。
</details>

## 13. 日志与故障排查

### 当前的可观测手段

本项目**尚未实现日志落盘**（见 [计划支持](#-计划支持--可扩展当前尚未实现)）。目前可用的信息来源：

| 来源 | 位置 | 内容 |
| --- | --- | --- |
| 界面错误条 | 主窗口预览区下方 | 最近一次操作失败的原因 |
| 模块错误行 | 各功能面板底部 | 该模块最近一次的 `lastError` |
| 状态指示 | 各面板状态灯与数值区 | 是否运行、当前读数、状态、NCC、条填充率 |
| 预览状态栏 | 预览区顶部 | 实际帧率、单帧捕捉耗时、抓帧方式 |
| 开发模式控制台 | `wails dev` 的终端 + `http://localhost:34115` devtools | 前后端完整调用与异常栈 |

### 排查建议

开发模式下排查最直接：

```bash
wails dev
# 终端可见 Go 侧输出；浏览器打开 http://localhost:34115 用 devtools 看前端与绑定调用
```

### 反馈问题时请收集

1. **程序版本**：Release tag 或 `git rev-parse --short HEAD`
2. **系统环境**：Windows 版本号、显示缩放百分比、屏幕分辨率、是否多显示器
3. **游戏环境**：窗口化/无边框、窗口像素尺寸、UI 缩放档位、是否以管理员运行
4. **复现步骤**：从启动到出问题的完整操作序列
5. **界面截图**：包含错误文案与相关面板（**注意遮挡个人信息**）
6. **校准文件**：`%AppData%\mxd\potion\calib.json` 内容（不含个人信息，可直接贴出）
7. **构建/测试输出**：源码构建失败时贴完整的 `wails build` / `go test` 输出
